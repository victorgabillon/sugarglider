# PR41 preparation — local canonical GPX export

Normal **Download GPX** now serializes the displayed canonical `PlanCandidate`
locally. The same action works for a generated candidate and an explicitly
stored offline route snapshot. It uses the candidate's existing route geometry,
profile and validated selected approaches, without an API request, generation,
rerouting, ranking or snapshot mutation. The browser download is offered even
when the optional server is unavailable.

This is one reviewable part of production Android integration. It does not yet
enable the release native routing factory, bundle first-launch assets, connect
normal Generate to local planning, or implement Android's document-save adapter.
Browser blob download alone is not evidence that Android's WebView can save a
file. The required PR41 release-equivalent Fairphone matrix remains open.

## Canonical data and export contract

The exporter accepts the existing `PlanCandidate`/`RouteResult`; it introduces no
parallel product result or breaking schema. GPX 1.1 contains exactly one track
and one segment. Trackpoints follow the returned geometry in order. No route,
analysis, POI/nature extension, elevation or timestamp is invented. Additional
input fields never enter the GPX. Dropped stops are omitted; approximated stops
use their validated routed approaches and are named approximate.

Both Python and shared-web writers order reached and approximated approaches
together by route progress, with a stable ID tie-break. The earlier Python writer
concatenated those two arrays, which could place an earlier approximation after
a later reached stop. Input candidates remain unchanged.

The local GPX trust boundary checks finite WGS84 positions, matching public
profile identity, distinct reached/approximated/dropped outcomes, approximation
bounds and selected-stop arrival. Arrival uses the same local metric projection
as Python; the measured distance must be within the approach's recorded strict
tolerance, and a reached stop's reported distance must agree within 2 m.
Projection only validates stops and never alters geometry.

Bounds are explicit: 200,000 track vertices, 64 exported stops and two million
stop/edge distance checks. Unsupported size or invalid input produces a useful
export error. All native PR34 routes fit the vertex cap; a large shared snapshot
may exceed the export work cap. There is no server retry or simplified line.

Coordinates use Python-compatible eight-decimal formatting, including exact
binary half-way rounding to even and negative zero. Filenames use the existing
Unicode normalization, ASCII sanitization and 100-character stem policy. XML
text strips invalid controls/surrogates and escapes markup.

`public_profile_metadata.js` is generated solely from the immutable Python
routing-profile registry. Its labels/activity kinds are available offline;
availability still requires installed native capabilities. It does not claim
GraphHopper/Valhalla equivalence. Regenerate and verify after registry changes:

```sh
uv run python -m sugarglider.web.build_profile_metadata
make check
```

The normal page imports `local_gpx_export.js` directly. The obsolete planning
GPX POST helper is removed from `api.js`; server GPX endpoints still serialize
stored candidates for external consumers. Service-worker shell **v26** includes
the two new modules and changed normal page/API. Cache fingerprints and the full
module allowlist remain checked; no route, GPX, data pack or API is precached.
