# Calculation lifecycle (#119)

An explicit visible Generate starts one native operation, identified by a random 128-bit ID and the existing bridge page nonce. One operation covers initial inference, local routing/Nature/elevation, optional second inference, publication and result selection. Standalone local generation uses the same operation boundary. Focus/resume handlers never start work. Activity pause still closes the OAuth foreground gate and cancels speech, but no longer cancels inference. The native connection/executor and operation registry belong to the application process.

## Android execution choice

A dedicated non-exported `dataSync` foreground service covers fetching the model response and processing the installed regional files. Android documents both data fetching and local file processing under this type. `shortService` is limited to about three minutes, insufficient for two existing 120-second calls and routing; WorkManager/job replay would not safely resume this streaming browser-controlled workflow. See [service types](https://developer.android.com/develop/background-work/services/fgs/service-types), [background start restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), and [timeouts](https://developer.android.com/develop/background-work/services/fgs/timeout).

The visible Activity starts the service before work. Inference waits for notification readiness. Notifications must be enabled; permission denial starts no work and requires an explicit Generate after granting permission. The generic notification opens the existing Activity or cancels the matching operation. It contains no description, route, account or coordinate. Cancel PendingIntents invalidate prior handles. The service is `START_NOT_STICKY`, stops promptly at completion/failure/cancel/destruction/system timeout, and has its own ten-minute maximum. One non-reference-counted partial wake lock, bounded by that same maximum and explicitly released, permits CPU work during screen lock. Neither service nor wake lock runs while idle. No location service, background location, alarms, jobs, boot receiver, auto-restart or permission for background recording is introduced.

The existing WebView is retained across normal pause and configured size changes. No `WebView.onPause` or global `pauseTimers` is called. Native replies and worker promises advance the existing pipeline. Android's default renderer priority remains important regardless of visibility ([WebView reference](https://developer.android.com/reference/android/webkit/WebView#setRendererPriorityPolicy(int,boolean))). These measures allow continuation when Android permits it; they cannot guarantee execution under process/renderer eviction, force-stop, device shutdown or restricted network access. Existing 120-second HTTP deadlines, model/schema limits, two-model-call cap and strict routing budgets remain enforced. OAuth callback receipt still waits for actual Activity resume before token exchange.

## Interruption and recovery

Activity destruction, page replacement and renderer loss cancel the owned channel and mark an interruption. Configuration changes already handled in place retain the operation. The existing navigation epoch, WebView identity, bridge nonce and request ledger still gate every delayed reply. A stale finish/cancel cannot end a newer operation. JNI routing drains before its actor closes; late cancelled responses cannot publish a candidate.

A separate AES-GCM/Android Keystore journal in `noBackupFilesDir` contains exactly schema, operation ID, kind, state and original user description. It contains no copied pins, geometry, model stream, account or authority. It is atomic, size-bounded and keeps one record. Successful completion and explicit cancellation remove it. Failure/interruption permits restoring or forgetting the original description. Restoring never starts inference, routing, recording or a service; Generate is the explicit retry and the UI explains possible additional ChatGPT usage. An interrupted stream is never resumed or automatically repeated. Completed adventure artifacts continue using the existing exact snapshot repository and GPX serialization. No historical progress or route reconstruction is introduced.
