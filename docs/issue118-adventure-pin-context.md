# Adventure pin context (#118)

Each new dialog excludes manual route pins. Only the selected installed region and activity preference are read when opening or generating without opt-in. Saved-adventure display requests are never a source of pins. Enabling the visible checkbox captures the editable manual pins once (at most sixteen, including endpoints), preserving names, identities and order. It does not infer, route, discover nearby places or make any stop compulsory. Oversized snapshots fail explicitly.

Start, End and up to fourteen exact intermediate points become hard requirements only through separate explicit controls. Disabling context clears those captured requirements; a location explicitly selected using Choose Start/End remains a separate user choice. Names are untrusted model data. No GPS, camera, geometry or automatic inventory is included. Local grounding still validates model-proposed places against the installed region after inference. Generate is the sending boundary. Reopening resets pin consent and captured requirements.

Validation uses deterministic model/native fixtures. The pin harness inspects the exact encoded model input for both languages, zero/one/sixteen/oversized snapshots, 200% text, snapshot immutability, separate fourteen-point requirements, explicit map selection, failure and reopening. Existing full application tests exercise manual-route/GPX preservation, saved-adventure display failures and exact snapshot recovery. No APK installation, region changes or live inference is part of these checks. Physical Fairphone validation, including the original 23.172 km route and byte-identical GPX, requires the device and separately authorized installation if a new binary is needed.
